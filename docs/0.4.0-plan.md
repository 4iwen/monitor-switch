# 0.4.0 feature plan

Implemented locally. Validation passed: 30 Rust tests, Clippy, browser settings
interactions and layout checks, and native macOS hotkey registration/conflict/
release checks. Originally developed locally as 0.3.0, these changes are released
as 0.4.0. Windows native hotkey and physical monitor behavior still need hardware
validation; CI verifies the Windows build.

Scope: optional global shortcuts and a per-display previous-input action.
No background polling, USB automation, or automatic shortcut assignment.

1. Configuration: preserve old files, validate combinations, register native
   hotkeys on the event-loop thread, preserve previous bindings on registration
   failure, and persist settings only after validation.
2. Switching: keep independent session history, ignore repeated observations,
   re-read the active source before switching back, and retain existing request
   version checks and nonblocking DDC workers.
3. Settings: record and clear combinations, pause hotkeys while recording,
   preserve drafts during refresh, and report failures inline.
4. Verification: Rust tests and Clippy; offline browser interaction tests in
   macOS/Windows styles, light/dark themes and minimum window size; local macOS
   installation. Windows native registration and physical monitor switching
   remain a separate Windows hardware validation step.

History records successful reads and commands accepted by the backend. A sent
command remains unverified until read back. History intentionally resets on app
restart so an old machine session cannot silently select an outdated target.

Developer UI check:

```sh
cargo run --example settings-preview -- /tmp/monitor-switch-settings.html
node scripts/test-settings.cjs /tmp/monitor-switch-settings.html
cargo run --example hotkey-check
```

The browser check requires Playwright and Chromium. Set `PLAYWRIGHT_CHANNEL` to
`msedge` to use an installed Edge browser in a separate headless test profile.
